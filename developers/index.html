MewCMS for developers

A Laravel CMS you can read.

MewCMS is a Laravel application with an Inertia and React admin. Themes and blocks are folders of TypeScript, CSS and JSON, so you can read, test and version them like the rest of your code.

The stack.

Laravel 12

Routing, security and persistence, on PHP 8.3 or newer.

Inertia 2

Server-driven pages with SPA navigation and no separate API to maintain.

React 19

The admin, the block editor and every theme page.

TypeScript

Typed props for pages, blocks and the data the CMS sends them.

Tailwind CSS 4

Design tokens the themes extend with their own colours and fonts.

Your database

SQLite to start, MySQL 8 or PostgreSQL in production.

Vite

One build for the admin and every theme, each in its own chunks.

AGPL v3

Free software. Change it, run it, and share what you change.

Run it on your machine.

You need PHP 8.3 or newer, Composer, and Node.js 20 or newer. SQLite is enough to start. The seeder creates the languages, a default site, the profiles and an administrator, and the default theme can load a starting home page, menus and a contact form.

Full install guide 
# Get the code and its dependencies
git clone https://github.com/fishercom/mewcms.git
cd mewcms
composer install
npm install

# Configure, create the database and seed it
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed
php artisan cms:content-import default
php artisan storage:link

# Start Laravel and Vite together
composer dev

A theme is a folder.

Each site picks a theme in the admin. A theme holds its stylesheet, assets, fixed texts per language, optional starting content and the pages it wants to change. Any page it leaves out comes from the default theme, so a theme with no pages at all simply restyles the default ones.

Themes can live in their own repositories: link the folder into resources/themes before you build, and the CMS repository stays clean.

Read the theme guide 
resources/themes/<slug>/
├── theme.json       name, version, author
├── screenshot.png   preview in Admin → Sites
├── css/theme.css    the theme's stylesheet
├── assets/          images and fonts
├── lang/            en.json, es.json, ...
├── blocks/          the theme's own blocks
├── content/         optional starting content
└── front/           pages, named like the Inertia components
    ├── layout.tsx
    └── templates/home.tsx, page.tsx, post.tsx

A block is JSON plus a component.

The JSON file declares the block’s fields, which the page editor turns into a form. The React component renders it on the public site and in the editor preview. Fields can be text, rich text, images, video, numbers, repeaters, a slider or a list of posts.

A theme can also restyle one of the CMS’s own blocks by adding a component with the same name.

// blocks/testimonial.json
{
  "name": "Testimonial",
  "icon": "quote",
  "fields": [
    { "key": "quote", "type": "textarea" },
    { "key": "author", "type": "text" }
  ]
}
// front/blocks/testimonial.tsx
import { type BlockRenderProps } from '@/blocks/types';

export default function Testimonial({ data }: BlockRenderProps) {
  return (
    <blockquote>
      {data.quote}
      <cite>{data.author}</cite>
    </blockquote>
  );
}

Texts that translate themselves.

Theme pages write keys, not words. The theme ships each key in every language it supports, and each site can change any of them from the admin without touching the code. Prices, dates and plurals are formatted for the page’s language.

php artisan cms:theme-texts lists every key that is missing a translation, and the test suite runs it on every theme.

import { useTexts } from '@/lib/theme-texts';

const { t, choice, price } = useTexts();

<h2>{t('footer.explore')}</h2>
<p>{choice('search.results', results.length, { query })}</p>
<span>{t('shop.from_price', { price: price(card.price) })}</span>
